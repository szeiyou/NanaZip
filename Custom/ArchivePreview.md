# 现代右键菜单中的内容树

按用户提供的 Win10 Bandizip 截图，预览应在同一面板直接列出缩进的文件树，
包含文件夹和文件图标。不显示“单文件夹/散文件/混合内容”分类，也不要求逐级展开。

Windows 11 下放在 NanaZip 的右键展开面板顶部，常用压缩/解压命令保留。
预览项只读，不打开或解压文件。文件/文件夹符号放在标题行内，按
“缩进 → 📁/📄 → 空格 → 名称”排列；每层增加两个 en-space，图标与名称一起缩进。
不再使用固定在左侧的原生图标列。行内符号由 Windows 字体渲染，颜色和造型依系统而定。
文件条目为正常亮度，点击返回成功且不执行操作；标题、空包和不可预览等状态说明保留灰色。

## 范围与预算

- 单选本地固定盘上的 `.zip`、`.7z`、`.rar`；多选与其他格式维持普通菜单。
- 按包内首次出现的路径顺序列出，补齐没有显式目录条目的文件夹。
- 展示最多 3 层、12 项；截断时显示“其他内容”，空包给出提示。
- `GetTitle` 不扫描归档。fast `GetState` 返回 E_PENDING，允许慢调用时才读取目录。
- 默认协作式预算 350ms、16MiB 输入读取量、10000 项、20000 节点、64 层路径；
  对支持内存请求回调的处理器提供 32MiB 解码内存上限。
- 这不是操作系统强制超时/进程内存沙箱：同步本地 I/O、库加载与处理器未主动回调的计算
  不能由该协作式预算保证硬截止，实际较慢时降级为无法预览。
- 跳过网络、设备、可移动盘、重解析点和云占位文件，避免联网或自动下载。
- 不提供密码和分卷打开回调；无法读目录、加密目录、损坏或达到限额时给出只读提示。
- 名称按单行展示，移除控制/双向格式字符并限制长度；冲突或不安全路径不伪造目录树。

## 构建与测试

`Custom/Build.ps1` 现在同时编译独立 Shell 扩展。源码在：

- `NanaZip.UI.Modern/ArchivePreview.cpp` / `.h`：只读目录加载、树结构、展示截断。
- `NanaZip.ShellExtension.cpp`：IExplorerCommand 慢路径、只读预览条目和随层级缩进的行内符号。
- `Tests/ArchivePreviewTests.py`：真实 ZIP/7z/RAR4/RAR5、隐式目录、中文、空目录、限额、截断和加密头。
- `Tests/ShellPreviewTests.cpp`：加载真实扩展 DLL，验证 E_PENDING 重试、菜单条目、缩进、图标及不可执行状态。

打包时对保留 GUI 的 Payload 再跑一次预览测试，检查依赖兼容；不注册或安装扩展。
新包须安装后由实际 Explorer 确认排版与宿主调用顺序。测试 COM 方法通过不等于已验证系统菜单渲染。

该功能与脚本改动保存在 `codex/custom`。已实测构建与 Payload 内依赖组合，
并经独立复核确认截断包错误标志、提前枚举后重试均有回归覆盖。
