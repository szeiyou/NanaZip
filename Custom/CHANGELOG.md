## 2026-10-16：处理反复等待更新的右键宿主

- 定位持续 pending 的实际占用者：加载旧版 ShellExtension/Modern DLL 的 NanaZip COM Surrogate。
  关闭主窗口不足以释放该后台宿主，重复安装也不会解除占用。
- 升级前没有 NanaZip 任务/窗口时，仅释放已核对 COM 类、当前会话、System32 路径及包模块的空闲宿主。
  有任务运行、身份不匹配或无法检查时保持延迟注册，不重启 Explorer 或其他 COM 进程。
- 加入“空闲宿主可释放”和“压缩任务/其他 COM 类/其他会话/其他路径/其他包不可结束”的回归。
- 已实际完成 7.0.1870.4 部署：应用和 Bundle 均为目标版本，Status=Ok，四个运行时 DLL 哈希匹配。
  该确认不等于已验证 Windows 11 菜单的实际排版。

## 2026-10-16：右键菜单内的文件树预览

- 在 NanaZip 现代右键子菜单中直接列出文件和文件夹，带图标与层级缩进，
  同一面板显示多层，无需逐级悬停。不显示单文件夹/散文件等分类标签。
- 首批支持单选 ZIP、7z、RAR；最多显示 3 层、12 项，更多内容显示省略提示。
- 仅读取归档目录；加密头、损坏、读取受限时显示无法预览，不弹密码框、不提取文件。
- fast GetState 返回 E_PENDING，由 Explorer 的慢路径读取目录，GetTitle 不做归档扫描。
- 排除网络、设备、可移动盘、重解析点和需要下载的占位文件；设置时间、读取量和目录条目预算。
- 独立编译 Shell 扩展，GUI 仍复用已有现代版；打包前测试实际 Shell COM 菜单的缩进、图标和只读状态。
- Windows 11 原生菜单控制图标列位置，与截图中 Win10 Bandizip 的绘制不保证逐像素一致；
  实际 Explorer 排版需安装后确认。

## 2026-10-16：建立自用构建流程

- `main` 保持上游代码，`codex/custom` 管理自定义改动。
- 新增 `Custom/Build.ps1`：自动发现工具，编译 x64 Release 核心和匹配插件，
  运行回归测试，再生成已签名的现代界面 `.msixbundle`。
- 将构建、测试、打包、验证及安装模板从临时目录纳入版本管理。
- 自动递增包版本，记录源码来源、界面来源、测试状态和文件哈希。
- 根据编译记录和源码指纹拒绝使用过期 DLL；通过 Windows SIP 校验签名覆盖的包内容，
  并测试更新外层哈希后仍能拒绝被篡改的 Bundle。
- 本地签名密钥进入被忽略的 `.custom-local/Signing/`，密码由当前用户的 Windows DPAPI 保护；
  后续构建复用证书，分发包只含公钥。
- 补齐中文构建、安装和上游合并说明。

限制：现代 GUI、中文资源和原版命令行仍复用现有 Preview 包；
优化 Core、Codecs、ZS.Codecs 来自源码。当前机器的完整 GUI 构建工具链尚未验证可用，
不能称为完整 GUI 源码构建。已确认此前 7.0.1870.0 包注册成功且核心哈希匹配；
本次新产物尚未安装，现代 GUI 启动仍待实际确认。

## 2026-10-16：修正安装流程

- 修复 `0x80073CF3`：已安装的官方 Bundle 必须用 `.msixbundle` 更新，不能替换为单包。
- 处理 `0x80073D02`：现有包 `UpdateWhileInUse=defer`，改用延迟注册，明确区分 pending 和 Installed。
- 安装前验证哈希、身份、证书和版本；拒绝降级，失败时导出日志和部署事件。
- 不自动卸载、结束压缩任务、重启资源管理器或关机。

## 2026-10-14：ZIP 性能优化

- 符合条件的未加密 Store/Deflate ZIP 采用最多 8 个工作线程提前解码，
  保持回调和文件输出顺序；缓冲上限 512 MiB，仍受用户内存限制约束。
- 多文件压缩按平均输入大小增大输出缓冲，保留总量和内存预算限制。
- 小文件、加密、分卷、符号链接、单线程及不支持的方法保留串行路径。
- 增加 ZIP 集成、API 回调、取消和 I/O 错误回归测试。
- 本机 6.09 GiB 音视频样本：压缩耗时约降低 21%，解压约提升 3.9 倍；
  压缩仍慢于同次测试中的 Bandizip，相同参数下 ZIP 与基线逐字节一致。

条件、数据和测量局限见仓库 `Documents/ZipPerformance.md`。
